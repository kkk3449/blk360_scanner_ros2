# Response to Reviewer 1 (electronics-4525706, Revision 1)


We thank the reviewer for a careful reading that engaged with the method at the level of individual thresholds and procedures. All eight comments led to concrete changes; the two largest are a new Methods subsection that consolidates every corrective procedure with its trigger conditions and parameters (Section 4.7), and a set of new quantitative analyses (threshold sensitivity, an independent matching scorecard, and a no-provisional-label ablation) that were run for this revision without any change to the underlying experiment data. Revisions are summarized below with their locations; all section numbers refer to the revised manuscript.

**Comments 1:** The TLS preprocessing part needs a few more details. For example, the authors should explain how the RANSAC process is stopped, how floor/wall/ceiling planes are identified, and how the point cloud is normalized.

**Response 1:** We agree, and auditing the code against the text while answering this comment also uncovered two inaccuracies in the original description, which we have corrected. Section 4.1 now specifies the full procedure: each RANSAC round draws 300 seeded random point triples, keeps the candidate with the most inliers at a 5 cm distance threshold (the originally stated 4 cm belonged to an unused code path; 5 cm is what runs), and refits once by SVD; a plane is removed only if structural by orientation (near-horizontal, |n_z| >= 0.85 — floors/ceilings — or near-vertical, |n_z| <= 0.2 — walls); and the loop stops at the first of four conditions: (i) ten planes removed, (ii) fewer than 2,000 points remain, (iii) the best remaining plane supports less than 4% of the points still present, or (iv) the best remaining plane is slanted (0.2 < |n_z| < 0.85), i.e., object-like. On normalization, the original sentence ("normalized so that the floor lies near z = 0") did not describe the running pipeline: no global normalization is applied; the cloud stays in the scanner's registered frame and the floor height is estimated per stage by robust statistics (the densest 5 cm height bin of the lower half-cloud for the remnant filter; the lower quartile of per-cluster bottoms for the map-based filter). Section 4.1 now states this explicitly. We thank the reviewer for a request that led to a genuine correction.

**Comments 2:** The structure-remnant filter is described a bit too qualitatively. Terms such as "thin vertical planar band" and "dense horizontal layer" should be supported by clear numerical thresholds so that others can reproduce the method.

**Response 2:** Agreed and done. Section 4.2 now defines the filter as five numeric tests that must all pass, with thresholds fixed once and used unchanged on every scene: (i) vertical extent <= 0.6 m with the bottom >= 1.5 m above floor; (ii) thin vertical planar band = best-fit plane |n_z| <= 0.25 with RMS off-plane thickness <= 3 cm; (iii) >= 40 pre-removal points in the band 2–45 cm above the cluster top within the footprint padded by 0.3 m; (iv) dense horizontal layer = >= 60% of those points concentrated in a ~7 cm slab around the modal 3.5 cm height bin; (v) topmost-layer test = the region 0.1–1.5 m above that slab holds <= 20% as many points as the slab. The second, map-based structure filter's thresholds are likewise now fully enumerated in the new Section 4.7 (wall-hug fraction defined as the fraction of points within 0.15 m of the nearest grid wall line, > 0.6, sheet minor extent < 0.22 m, full-height z-span > 2.5 m with along-wall length > 2 m, ceiling band > 2.0 m, outside-room fraction > 0.5).

**Comments 3:** The VLM voting and fusion process should be explained more clearly. In particular, please give the exact confidence-weighted fusion rule and explain why 0.6 was chosen as the final verification threshold.

**Response 3:** Both are now in the paper, and we added a quantitative analysis of the threshold. Section 4.4 gives the exact rule: each label accumulates the sum of the confidences of the views voting for it, s(l) = sum of c_v over views with label l; the fused type is the argmax and the vote share is sigma = s(top) / sum over all labels; unanimity means exactly one distinct label. The 0.6 value was fixed a priori as the smallest round threshold demanding a clear supermajority of confidence mass (at 0.5, a vote split between two equally confident labels could verify on a tie-break), and it gates status only — the fused label is recorded either way. Because status is a pure function of stored votes, we could sweep the threshold exactly with zero new verifier calls: the new "Threshold sensitivity" paragraph in Section 5.3 shows 0.6 sits on a plateau (0.55 and 0.60 produce identical tiers on the showroom; F1 is maximized on a broad 0.45–0.65 band on all three scenes; between 0.50 and 0.70 only 11/34, 12/49, and 7/19 escalated objects change tier), so no alternative threshold dominates it by more than single-object noise, and we retain the a-priori value rather than tuning post hoc.

**Comments 4:** It would be useful to test whether the provisional Uni3D label affects the VLM decision. Since this label is given to the VLM as input context, an ablation without this label would help show whether the VLM is truly correcting Stage-A errors.

**Response 4:** We agree this is a valuable control and ran it for this revision (new "Provisional-label ablation" paragraph, Section 5.8). The full showroom protocol — same renders, same verifier, base four views plus automatic escalation — was re-run with the provisional label removed from both the system prompt and the per-object context, with dimensions and all perceptual guardrails retained. The result answers the reviewer's question in both directions. With the label, Stage B genuinely corrects Stage A: it departs from the Stage-A label on 8 of 36 confirmed-GT objects, 5 correctly and 3 incorrectly, lifting 77.8% (Stage A alone) to 88.9%. Without the label, the verifier is not an independent classifier: the trigger rate rises from 58% to 90%, unanimity collapses from 21 to 5 objects, escalated accuracy falls to 38.9%, and 22 of its 26 departures from the Stage-A label are wrong — generic clutter loses its anchor (12 vs. 23 clutter answers against 22 in GT) and specific-type accuracy halves (10/14 → 4/14). Importantly, the failure is routed as designed: blind uncertainty flows into the unverified tier (38 vs. 21 objects) rather than into confident errors, though verified-tier precision erodes. The revised text draws the honest conclusion: Stage B is a verifier of hypotheses, the provisional label is load-bearing context, and this same anchoring power is why label adoption elsewhere in the framework is agreement-gated and owner-auditable rather than trusted outright.

**Comments 5:** The object matching strategy across different scans needs clarification. If several old objects satisfy the matching conditions at the same time, how is the final match selected? The choice of the 0.5 m, 30%, and 6 m thresholds should also be explained.

**Response 5:** Section 4.5 now specifies conflict resolution exactly: when several nodes satisfy the predicate for one record, the record claims the nearest node by horizontal centroid distance; when several records compete for one node, the first claim locks it (greedy, in the backbone's deterministic record order), and later records fall through to the move pass and then to insertion. We state honestly that this is a greedy assignment rather than a global optimum, chosen for simplicity and reproducibility — and the new matching scorecard (Section 5.6) reports the observed conflict counts on the real transitions: zero multi-candidate conflicts in the spatial pass on both transitions and exactly one in the move pass, resolved to the owner-confirmed chair move. The thresholds are physical priors fixed on the development epochs: 0.5 m is far above the <= 5 cm registration residual yet below expected inter-object spacing for stationary objects; the 30% extent band (with a 0.15 m absolute floor so small objects are not over-constrained) absorbs partial-view truncation between scans; 6 m bounds a within-room relocation.

**Comments 6:** The DBSCAN sensitivity analysis may be somewhat circular. The selected operating-point segmentation is used as the reference when evaluating other parameter settings. An independent object-level reference would make this comparison more convincing.

**Response 6:** We agree, re-scored the entire 36-combination sweep against an independent object-level reference, and also report an error that the re-scoring uncovered. The independent reference is the owner-audited inventory in a membership-independent form: all clean-cloud points falling inside each owner-audited oriented bounding box, so no clustering decision defines the reference (box geometry validated against the owner dimensions at 0.000 median relative error). On the robot hall (42 reference objects) the original conclusion survives intact: the min-points-100 band is a broad plateau and the operating point (0.30/100/2.5 m) sits at the grid maximum under the independent reference (recall 0.952 = 40/42; the cluster-referenced numbers are a uniform ~0.05 higher with identical plateau shape). On the showroom, however, the audit revealed that the original sweep rows had joined the reference onto the operating run's own clusters — exactly the circularity the reviewer suspected — and against the genuinely audited 57-object inventory no base-clustering setting exceeds recall 0.33: that scene's audited granularity is produced by the downstream split-refinement stage, not by DBSCAN parameters. Section 5.2 now reports the corrected framing: the showroom rows are evidence for the necessity of the refinement stage, and the parameter-robustness claim rests on the non-circular robot-hall table. We thank the reviewer for prompting a check that materially corrected the paper.

**Comments 7:** The ground-truth labeling process may introduce some bias. Since the owner saw the proposed model labels before making corrections, the authors should discuss this possible anchoring effect and, if possible, provide independent or blinded annotations.

**Response 7:** We did both. The anchoring channel was already disclosed in Section 5.1; for this revision we additionally obtained a blinded second annotation and measured the effect directly (Section 5.1, Ground truth). A second annotator — a co-author familiar with the facility who had seen neither the T3 pipeline output nor the owner audit — labeled all 41 T3 clusters from full-resolution multi-view render sheets carrying only neutral, shuffled IDs (no system, VLM, or owner labels), in free vocabulary with a 1–5 confidence. Results: on the 33 clusters both annotators labeled, the blind labels agree with the owner's on 31 (93.9%); the two disagreements are low-confidence blind labels (2–3/5); the blind annotator abstained on 5 and both were uncertain on 2. The most relevant comparison for anchoring is the split by whether the owner had overridden the model: on the 31 clusters where the owner overturned the pipeline label, the blind annotator independently reproduced the override on 25 of the 26 it scored, versus 6 of 7 where the owner had accepted the model. The 25/26 reproduction of the owner's overrides argues against those corrections being driven primarily by model anchoring; the accepted subset is small (6/7 agreement), so residual anchoring cannot be excluded, and the revised text says so. We describe the owner ground truth as anchoring-bounded rather than anchoring-free, and we retain the original disclosure of the channel. We note that the second annotator is a co-author (independent of the pipeline output and of the owner audit, but not an external evaluator); the revised text states this. The blind kit, answer sheet, and scoring are included in the data package.

**Comments 8:** Some important corrective steps are introduced mainly in the Experiments section. Procedures such as re-splitting, the structure-condition ensemble, and owner-driven correction should be described more clearly in the Methods section, including when they are triggered and which parameters are used.

**Response 8:** Agreed — this was the largest structural change of the revision. The new Section 4.7 ("Corrective Decomposition Layers and Owner Feedback") defines all five corrective layers with their trigger conditions and every numeric parameter: (1) diffuseness-gated re-split (trigger: 2-D occupancy fill < 0.30 with footprint > 5 m²; occupancy-core erosion with cells >= 8 points and >= 3 occupied neighbors; evidence gate >= 250 points, >= 5 m² — 12 m² for desk banks — and >= 0.15 m height); (2) wall-compound gate (trigger: >= 25% of points within 0.12 m of the grid wall line over >= 2 m span with >= 250 protruding points; including the panel square-up finishing pass with its 6 cm/5 cm re-assignment margins); (3) structure-condition ensemble (every epoch; three removal conditions; VLM only on new candidates; cross-condition agreement stored as labelStability, never used as a label fuser); (4) hybrid grid-map structure filter (fixed rule cascade, thresholds as in Response 2); (5) owner feedback and agreement-gated recovery (adoption only on cross-pass agreement or agreement with the base label; tie-break accepted only within the disputed pair at confidence >= 0.6). Section 5 now reports only what these layers did, with cross-references to the definitions; Section 4.6 additionally consolidates the object record, tier set, matching function, and upsert cascade into a single formal summary.
